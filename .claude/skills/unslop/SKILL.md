# Unslop：ZJ 原生界面适配

本 skill 改编自 [heydamir](https://github.com/heydamir) 的 [unslop](https://github.com/heydamir/unslop)，采用 [CC BY 4.0](LICENSE)。保留原作者署名；ZJ 适配和省略项见 [UPSTREAM.md](UPSTREAM.md)。

目标是让项目浏览、代码阅读、比较和 Git 操作更清楚、更顺手。优先解决信息与交互问题，再改善外观；不要为了「有设计感」引入装饰或重做整个工作台。

## 使用边界

- 项目 `CLAUDE.md`、用户当前要求和已有授权优先于本 skill。先读项目规则，再读 [GPUI 适配约定](references/gpui.md) 与[联合流程](references/combined-workflow.md)。本 skill 负责视觉方向和打磨，[GPUI 官方指南](../gpui-kit-design-guides/SKILL.md)负责原生任务、组件与交互；按同一流程完成一次改动，不递归调用彼此。
- 原版 [审阅清单](references/signs.md) 用于发现问题，不是强制改造项。清单中的 Layout pass 等章节名对应 [完整原入口](UPSTREAM-SKILL.md)；结合本文件九项检查使用。先读原入口的方向与 Layout pass，视觉内容相关时读 [参考说明与原图](references/refs.md)，其余原始参考按需读。Web、营销页、图表和品牌重设规则不自动适用于 ZJ；原文中的工具、脚本和等待批准流程服从本地适配。
- 默认局部打磨：在授权区域内可以重组信息、比例、对齐和留白，保留既定主题、字体、内容、功能与保护机制。仅修改本次问题涉及的区域及其共用入口。
- 用户已经要求修复或给出方向时，说明具体取舍并执行，不重复索要批准。仅审阅请求则只报告；只有确实缺少会改变范围或结果的决定时才询问。
- 截图是界面证据，不是代码或行为证据。核对对应渲染入口、事件与状态流；不要把重建的 HTML 当作原生应用交付。

## 执行顺序

1. **看实际界面。** 从用户截图、复现步骤和局部代码建立证据。能按授权运行原生界面时再观察；已有权限限制须如实记录，不绕过、不擅自连接服务。
2. **列具体问题。** 每项写「位置 → 用户遇到的障碍 → 最小改法」。同时查看信息主次、反馈是否打断、内容是否可选择／复制、键盘与焦点是否可用。没有发现问题时明确说明，不为了套用清单而改动。
3. **写短方向。** 按联合流程写 Product、Character、World、Moments、Signature 五行，针对当前任务决定视觉重心、密度与精细处理；沿用既定主题与字体，避免每次复述同一套「简洁、现代」标签。方向须能指导后续比例、层级与细节取舍。
4. **按以下九项依次检查。** 不相关项记为不适用；不要为了完成九项扩大改动。
5. **验证同一条用户路径。** 先复现交互问题，再修复和回归；检查真实动作、焦点、剪贴板和结果，不能只设置内部状态。布局与交互测试不能替代原生视觉验收。
6. **简短交付。** 说明问题、改变、真实检查结果与未验证范围。执行项目要求的独立审查及检查，不额外制造审查或批准流程。

## 九项检查

1. **间距。** 复用 `theme.rs` token 与现有 4 px 网格及已有例外；同类行、控件和图标对齐。组内间距小于组间间距。不要套用上游网页侧栏、行高和留白数值。
2. **颜色。** 保留两套现有主题；正文和次要文字达到项目对比度要求。颜色表达选择、变更、错误等含义。Git 红绿和语法高亮不是应删除的装饰。
3. **图标。** 使用已内嵌的 Lucide 与现有文件图标；只有图标的按钮必须有可访问名称。图标不能代替不清楚的动作文案，也不新增无含义图标。
4. **文案。** 先说结果，再给下一步；短、具体、自然。不编造数量、完成状态或成功。有界的 Git 输出与诊断信息在用户明确动作下展开并可复制，保留截断说明，错误不能被隐藏成成功或无变化。
5. **字体。** 沿用界面及代码字体、默认字号和缩放；层级靠必要的大小与颜色区分。不引入网络字体、展示型大标题或满屏粗体。
6. **布局。** 为当前任务保留空间。少量状态不占据大块侧栏；详细路径、元数据和原始输出不默认挤占主流程。窄窗口下仍能读到结果并触达操作；浮层不能抢走未完成输入。
7. **细节。** hover、键盘焦点、禁用、进行中、成功、无变化和失败均有明确含义。只读内容通常仍应能选择和复制。关闭或切换后不残留错误选区、旧结果或丢失焦点。
8. **视觉内容。** ZJ 的主要内容是代码、Diff、Markdown 和真实图片。不要添加营销插画、虚假数据、占位图表或无意义卡片。
9. **动效。** 默认静态。反馈如需自动消失，使用有结束条件的一次性任务；不新增闪烁、常驻轮询或持续重绘，也不自动增加图片生成／视频工具。

## 操作反馈专项

以下是 **ZJ 本地适配规则**，不是上游 unslop 对 Git 的原文规定。

- **无变化：** 如「已是最新」，默认一行紧凑反馈；诊断元数据放入「查看详情」。
- **成功有变化：** 优先显示真实结果，如「已拉取 3 个提交」；没有可靠数量时用准确的定性结果。
- **失败或部分完成：** 保留原因、需要用户处理的状态和可执行动作，直到用户处理或明确关闭；不能自动消失成成功，也不能丢弃原始错误。
- **进行中：** 明确正在执行什么、防止重复操作；完成或取消后结束临时状态，不引入常驻动画。
- **详情：** 保留所属仓库、分支、实际操作范围和脱敏后的原始输出，可选择、复制；主界面已经清楚表达的内容不重复堆放。只有确实实现了详情入口时才能收起正文。
- **完整性：** 首次发布、远端目标确认、危险写入确认、错误提示及凭据脱敏不能以美化为由移除。通知自动消失不等于删除可追溯的详情。
