# unslop 与 GPUI 的联合流程

这是 ZJ 的本地适配流程。unslop 的作者与 CC BY 4.0 说明见 [UPSTREAM.md](../UPSTREAM.md)；原生设计依据见 [GPUI Kit Design Guides](../../gpui-kit-design-guides/SKILL.md)。用户当前要求与项目 `CLAUDE.md` 优先。

## 分工与边界

| 议题 | 主要依据 | 另一份规则如何配合 |
| --- | --- | --- |
| 任务、对象、动作承诺、状态、键盘与焦点 | GPUI Kit Design Guides | unslop 检查表达和呈现是否自然 |
| 视觉方向、留白节奏、字体层次、表面对比、图标与细节 | unslop | GPUI 核对组件语义、桌面密度、可访问性和版本可用性 |
| 主题、token、400 px 侧栏、资源、权限和数据保护 | 项目 `CLAUDE.md` | 两份上游指南都不能覆盖 |
| 最终质量 | 同时看视觉完成度与真实交互 | 功能通过不代表美观，静态参考图好看不代表原生实现正确 |

不要把两份 skill 变成两轮独立重设计，也不重复调用彼此形成循环。使用任一入口时，按本流程组织一次任务；已经读过的相关规则直接复用。

## 1. 看清任务与现状

读 GPUI 指南的 `Design thesis`、`Start from the task` 及当前区域相关章节。明确用户要做什么、当前对象是什么、主动作与次动作、状态所有者、键盘路径和操作结果。

对照实际截图／窗口与代码建立问题清单：位置、问题、对用户的影响、改进目标。先排出真正妨碍阅读、理解或操作的点，不从组件清单或通用 dashboard 模板开始。

## 2. 写出视觉方向

沿用 unslop 的五行方向，并针对当前区域给出具体决定：

- **Product：** 本区域帮助用户完成什么，而不只写产品大类。
- **Character：** 选两三个具体特征，说明会怎样体现在层级、密度与表面上；不只写「现代、简洁」。
- **World：** 结合代码阅读和项目查看语境，沿用既有主题与字体。
- **Moments：** 当前真正值得突出的内容，如代码变更、当前文件、操作结果。可以有明确的视觉重心，不额外制造插画、卡片或图表。
- **Signature：** 一个适合当前任务的精细处理，如路径层次、行号与正文对齐、快捷键提示的一致性；不要变成每处重复的装饰。

使用已有用户授权继续。局部修整可重组授权区域的信息、比例、对齐和留白，不只删文案；保留功能和保护机制。需要改变用户明确确定的主题、侧栏宽度或产品范围时，不能把它当成常规打磨。

## 3. 按 unslop 的九项顺序打磨

间距 → 颜色 → 图标 → 文案 → 字体 → 布局 → 细节 → 视觉内容 → 动效。

每项记录具体改动或不适用理由，不要求为九项各造一个改动。重点看整体的对齐、节奏、视觉重量、前景／背景关系与阅读顺序。需要新尺寸或语义角色时，在 `theme.rs` 定义有意义的 token，而不是被现有 token 限制到只能做表面删减。

参考 [signs.md](signs.md) 和 [refs.md](refs.md)；开始前看与任务最相关的原图。五张原版参考图保存在 `refs/`，包括宣传视频的八帧分解图。借鉴其构图、层级、克制和逐步修整方法，不复制金融 dashboard 的卡片、配色或图表。

`tokens.md` 的网页尺寸／配色只是上游参考，`visuals.md`、`effects.md` 的生成与 Web 代码工作流不自动执行。本次没有安装上游脚本或生成工具。只有确实需要且获授权时，另行使用与原生目标匹配的工具；不能交付 HTML 替身。

## 4. 用 GPUI 规则落地并验证

核对原生组件、Actions、焦点、键盘、浮层关闭、滚动归属、选区与只读复制；实际 API 以锁定的 GPUI Kit 0.7.1／vendor 为准。保留静默刷新、错误可见、输出有界／脱敏及异步 generation 校验。

根据改动检查亮／暗主题、正常／窄窗口、长内容、进行中／成功／无变化／失败等相关状态。出现交互缺陷时，先有能捕获真实用户路径的回归，再修复。

## 5. 对照视觉目标验收

检查实现是否达到第 2 步的方向，而不只问「测试通过了吗」。在已授权且可用的原生验收路径中观察真实窗口；有截图时对照修改前后，看同一范围、尺寸和代表性内容。

仅通过无头测试、复制参考图或完成一份清单，都不能宣称原生视觉验收通过。截图／窗口权限阻塞时如实写明；不擅自连接服务或绕过权限。按项目规定完成审查与检查，不为同时使用两份 skill 再增加重复审查。

交付说明改了什么、为什么、实际验证及限制。宣传视频是展示改动的方法，不是 ZJ 运行时效果要求；是否另做演示视频由用户明确提出。
