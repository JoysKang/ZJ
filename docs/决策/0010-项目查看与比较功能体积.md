# ADR 0010：项目查看与比较功能的体积和内存预算

日期：2026-11-04。状态：已采纳。

## 背景

用户要求实施《项目查看与 Diff 功能缺口》中的全部剩余项目，包括独立图片查看、图片比较、Git 管理、文件和历史比较、阅读恢复、编码只读视图及常见编辑交互。按 `CLAUDE.md`，二进制增加超过 200 KB 或空闲 footprint 增加超过 5 MB，需要单独记录。

## 决定

复用已有依赖和组件：把 `image 0.25.10`、`resvg 0.46.0`、`encoding_rs 0.8.42` 从传递依赖改为直接依赖，不新增 package，不开启新的解码 feature。前两者保持 `default-features = false`。系统 Git 继续承担仓库操作，Git 查询、文件解码和全文解析在后台执行。

依赖树命令 `cargo tree -e normal --target aarch64-apple-darwin --prefix none | sort -u | wc -l` 的输出为 608 → 609；新增一行是 `resvg v0.46.0 (*)` 的重复引用标记，锁文件没有新增 package。这是输出行数变化，不是新增一个第三方包。

接受本轮必要功能带来的体积增量。以下数据来自相同机器的本地 dist 包，资源测量均为 `tools/measure_budget.py --runs 3 --idle-seconds 10 --skip-latency`，使用隔离设置和临时文件；未连接真实远端。

| 指标 | 400 px 布局基线 | 最终包（两阶段审查修复后） | 差值 |
| --- | ---: | ---: | ---: |
| stripped 二进制，bytes | 46,524,112 | 47,236,336 | +712,224 |
| 单窗口文档空闲 physical footprint，MB | 59.852 | 60.409 | +0.557 |
| 欢迎页空闲 physical footprint，MB | 54.560 | 55.002 | +0.442 |
| 3 窗口及 20 文档，MB | 143.623 | 136.726 | −6.898 |
| 文档空闲 CPU p95，% | 0.0145 | 0.3830 | +0.3685 个百分点 |
| 冷启动中位数，ms | 192.276 | 194.451 | +2.175 |
| 最慢一次冷启动，ms | 1,660.928 | 525.637 | −1,135.291 |

三次运行的观测不证明最坏启动时间达标。两个构建都有一次超过 400 ms 的启动样本；最终包的中位数在 250 ms 目标内，最慢一轮仍超上限，因此不能宣布完整启动验收通过。空闲 CPU p95 在 1% 上限内，但高于 0% 目标；测量期间文档与欢迎页均为 0 出帧、0 次 display link 唤醒。样本量和机器当时负载会影响这些差值，不能把多窗口数值降低归因为本轮优化。

最终 dist 与 `.app` 的 SHA-256 一致：`4d715e29a9b4486b6a2ae5ebc2052ab73b876119d16a926b9993596e71d44d25`。原始摘要、基线及测量命令保存在[功能补齐资源数据](../验收/数据/2026-11-04-功能补齐资源.json)，首次试包数据由本次最终包测量取代。

## 代价与后果

- 独立图片查看与图片比较共用全进程 64 MiB 的保留像素和在途像素分配预算，单文件最多 16 MiB，每窗口最多 8 个独立图片标签。先检查尺寸再分配，关闭时释放像素和窗口图像引用；这不是进程总内存、GPU 缓存或解码器临时内存的上限，也不代替原有 Markdown 图片加载边界。
- 两侧图片按实际解码用量顺序扣减共享预算，空侧不预占一半。全局原子预留继续防止并发窗口超额。预算用尽时显示错误，不自动关闭其他标签，也不放宽生产限制来满足测试。
- GIF／WebP 只显示首帧；SVG 不解析外部或嵌入 raster 图片；系统字体数据库后台加载并复用。编码视图严格解码且只读，不增加隐式转码写入。
- 最终包低于 50 MB 的体积目标、单窗口 70 MB 和多窗口 220 MB 的内存目标。此结论仅覆盖本次普通文本资源夹具，不代表加载大图后的 footprint。
- 未测完整屏幕呈现延迟、原生亮暗视觉、中文输入法和长时间压力。`--skip-latency` 不测按键延迟；像素与无头布局回归不能替代原生屏幕验收。
