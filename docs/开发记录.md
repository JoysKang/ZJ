### 2026-11-10 Python 导入直接跳到对应文件

- 用户反馈从 `from db.models import TransactionsHistory` 跳转时，工作区里多个同名 `models.py` 都会列出，即使导入语句已经指明了模块。原因是 `symbols.rs` 的候选排序只把 import 拆成扁平名字，文件只用 stem（`models`）比较，同名的模块无法区分；没有 LSP 时，最后只能退回候选列表。
- 现在 `imports.rs` 额外解析 Python 的点分模块路径（`import a.b as c`、`from ..db.models import X`、`from . import helper`），`symbol_index::imported_definition` 按导入文件所在目录及其祖先（对应常见 `sys.path` 项目根）拼出 `db/models.py` 或 `db/models/__init__.py`，包优先于同名模块，与 Python 一致。恰好一个候选落在这个文件时直接跳转；没有命中或多个命中时仍显示候选列表。
- 只处理 Python：其他语言、运行时才改 `sys.path` 的动态导入，或同名模块都不在导入文件的祖先目录下时，行为不变。`imports.rs` 仍只读行首的 import 语句，注释和字符串中的同形文字不会生效。
- 回归：`an_import_names_the_file_among_same_named_modules` 覆盖两个同名 `db/models.py` 时跳到导入文件旁的那个，以及导入工作区外模块时仍列出两个候选；去掉新解析时得到 2 个目标并失败。`python_modules_keep_the_dotted_path` 覆盖别名、多行、相对层级和 `from . import x`。
- 按用户要求打包（未提交）：`CARGO_NET_OFFLINE=true CARGO_HOME=target/cargo-home /bin/sh tools/package.sh` 实际 65 秒、exit 0；`target/dist/workspace-editor`、`target/ZJ.app` 与 `/Applications/ZJ.app` 的可执行文件 SHA-256 均为 `dced1941a630be95bf8ca642b0feda9b9137168f4ed8b51712dbd062e979f2a5`，大小 **47,319,232 bytes**。核对 `Info.plist`、图标与 ad-hoc 签名一致后原子替换可执行文件；运行中的实例（pid 39535）来自 `target/ZJ.app`，未关闭或重启。
