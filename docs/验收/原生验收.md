## 快捷键：根因与复验

初测在 `ca4f0b63` 上出现「编辑器聚焦时 ⌘S／⌘P／⌘,／⌘W 无反应，移焦或菜单有效」。根因不是键绑定：验收脚本把 IME 预编辑文本当成了已提交文本。AX `value` 在组合期间就更新，磁盘缺少标记被误判为保存失败；`defaults read ... AppleCurrentKeyboardLayoutInputSourceID` 只反映键盘布局，不能代表实时输入法模式，Escape 还会取消标记，原「已排除 IME」结论撤回。

进程内探针（临时补丁，验证后已撤销）确认：

```text
input focused=true marked=false contexts=[Root, WorkspaceEditor, DocumentEditor, Input]
cmd=true composing=true ime=true        # 组合期间 Command-S 被输入法消费，未进 GPUI KeyDown
composing=false → dispatch handled=true → event=document_saved bytes=52
```

`vendor/gpui-pre-macos/src/window.rs` 的 `handle_key_event` 在存在 marked text 时先交给 `inputContext.handleEvent`（含 Command 组合键），这是上游已有行为，没有依据修改。AX `AXFocusedUIElement` 回退到 `AXWindow` 是 Kit 把 role 放在外框、真实焦点在内部 `InputBaseState` 所致，不能据此判断 GPUI 失焦；无头 `window.press` 绕过 AppKit 输入上下文，覆盖不到该现象。修正落在验收脚本与报告，未改产品绑定。

复验（`tools/check_native_shortcuts.py`，退出码 0，实时源微信拼音前后一致，PID 87022 以 `-15` 回收）：未提交时 Command-S 不写盘；Return 提交后 Escape 保留全文，物理 key code 1 与 keystroke 两种 ⌘S 均写盘且全文等于 AX 文本，⌘P、⌘,、⌘W 全部通过。一次 ⌘, 断言失败是夹具漏了 `hidden_files`，ZJ 按既有迁移规则补默认规则，补成显式空数组后通过。
