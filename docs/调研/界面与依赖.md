## Web 组件不能直接用（2026-10-11）

| 项目 | 形态 | 结论 | 许可要点 |
| --- | --- | --- | --- |
| beUI | React + Tailwind + shadcn 注册表 | 只能参考外观，Rust 重写 | MIT，保留声明 |
| Rare UI | React 动效组件 | 不能移植分发 | MIT + Commons Clause + 署名；禁止再分发组件本身 |
| Transitions | CSS/React 动效片段 | 只参考参数 | 动效与 skills 自定义许可，工具目录 MIT |
| shadcn/ui | Web 源码与注册表 | 理念参考 | MIT |
| Beautiful UI | Next.js + React + Tailwind v4，21 个 AI 界面组件 | 只能借鉴设计 | MIT；SidebarNav 依赖付费 `@central-icons-react` |
| Zed UI | 基于 GPUI | 布局／排版参考 | `crates/ui` 为 GPL-3.0-or-later，且依赖 Zed 工作区模块，不能整包搬入 |

统一判断：四类 Web 方案都没有官方 GPUI 实现；引入 WebView 或整体改 Web 技术会增加渲染、焦点、输入法与滚动整合成本，当前没有采用理由。原 `longbridge/gpui-component` 已迁移为 `longbridge/gpui-kit`，不是两套候选。

可借鉴的视觉规则（设计参考，不是照抄数值）：低饱和冷色底、分层表面、主次文字、细边框、单一强调色；圆角分级（chip/control/card/window 约 6/8/10/14 px）；动效必须有结束时间，只在可见且交互时发生。ZJ 的 Solarized Dark / Nord Light、4 px 网格、正文 7:1 对比度要求优先。

来源：<https://beui.dev/>、<https://rareui.com/>、<https://transitions.dev/>、<https://ui.shadcn.com/>、<https://www.beautifului.dev/>、<https://github.com/zed-industries/zed/blob/main/crates/ui/Cargo.toml>。

## GPUI Kit 0.7.3 与 GPUI Fast（2026-10-12）

| 项 | 事实 | 判断 |
| --- | --- | --- |
| Kit 0.7.3 | 2026-10-12 发布，替代撤回的 0.7.2，固定 `gpui-pre =0.3.9` | 不是纯版本号更新 |
| 0.7.3 变化 | 减少未变化帧的状态写入；TextView 段间距 `1rem → 0.75rem`，标题／列表排版变化 | 需视觉回归 |
| GPUI Fast 0.1.7 | 独立 GPUI 分支，保留视图／滚动层／原生合成；Kit 用可选 `gpui-fast` feature 选择 | 实验性 |
| 官方基准 | Linux release：未变化窗口 3.31→0.19 ms，侧栏滚动 5.95→0.79 ms，行情更新 5.06→1.35 ms | 非 ZJ 实测，非同条件对比 |

不启用 Fast 的理由：保留视图、layout nodes、GPU tiles、overscan 都要缓存，外部可变状态需正确通知；ZJ 的低内存策略依赖「稳定空闲时停止出帧」，与「未变化帧更便宜」是不同指标，官方资料没有证明总内存下降。

迁移门槛（逐项，不能靠原 patch 自动转接）：

- 双缓冲、延迟纹理、闲置／遮挡回收、共享图集、shader 复用：需在新 renderer 上重建并处理滚动缓存生命周期。
- display link 空闲暂停／唤醒、遮挡恢复强制 present：需以真实空闲帧／唤醒计数验证。
- 常亮光标：0.7.3 仍有 500 ms 闪烁定时器，需重基补丁。
- 行尾 blame、审阅后视口 intent、代码块通栏标题、当前行背景右内边距：Kit 对应模块没有这些扩展。
- 通知默认声音、前台声音、等待授权时序：Fast 通知未设置声音，提交直接跟在异步授权后。

基线（当时）：aarch64 dist 29,661,520 字节，依赖树去重 615 行；没有候选数据。

来源：<https://github.com/longbridge/gpui-kit/releases/tag/v0.7.3>、<https://github.com/longbridge/gpui-fast/tree/v0.1.7>。

## 升级阻塞与核验标准（2026-10-22）

- 2026-10-22 crates.io API、Rust stable channel、GitHub Release API、Rust 博客与 Diff 产品文档全部被 WebFetch 域名安全校验阻断；没有用代理、curl 或安装命令绕过。
- 构建缓存补查：Kit／base／component 0.7.3 无源码与归档；GPUI／apple／macos 0.3.9 只有 sparse-index 记录（2026-10-12，`yanked: false`、`rust_version: null`），仍缺源码与 Kit 配套依据。缓存不能替代官方 non-yanked 与 checksum。
- 2026-10-12 旧报告记录的 0.7.3／Fast 只是本地历史记录，不能直接改锁文件。
- 后续核验标准：读 stable channel 的 `date` 与 `[pkg.rust].version`；crates.io 逐版本检查 `num`／`yanked`／`created_at`／`rust_version`，按 SemVer 取无预发布后缀且未撤回的最高版本，再核对官方 Release 与 manifest。`latest`、主分支文档、名字里的 `pre` 都不能单独证明发布通道。
- 顺序：核验版本 → 单独升 Rust → 升 Kit 与其指定 GPUI 快照并迁移 vendor → 功能与资源验收；Fast 另行评估。Rust 单独提交，便于区分新增 lint 与 GUI 变化。
- 门槛已更新：二进制 52 MB、单窗口 100 MB、3 窗口＋20 文档 300 MB、空闲 CPU p95 ≤1%（2026-10-22 调整）；旧报告的 32 MB／0.1% 不再适用。

`vendor/` 必须保留的行为清单见 `vendor/README.md` 与 ADR 0005；`ZJ_GPU_LOWMEM=0` 只能用于相关资源策略 A/B，不代表所有补丁都有开关。

## Diff 交互候选（2026-10-22，均为待一手核验的设计建议）

已实现基线：`diff_doc.rs`（两侧全文、语法／字符高亮、行索引，上限 200,000 行）、`diff_view.rs`（虚拟列表、左右／内联、块导航）、`diff_ops.rs`（选择、复制、块／行级暂存）、`agent_review.rs`（逐块／整文件接受或拒绝）。

| 候选 | ZJ 增量 | 成本 | 未决 |
| --- | --- | --- | --- |
| 未改动区折叠 | 显示投影保留上下文与展开按钮；选择、复制、跳转、暂存映射原始行 | 中；不释放两侧全文与高亮内存 | 绘制行减少不等于内存减少 |
| 跨文件审阅队列 | 一次只加载当前文件，记录待审／已处理 | 中；元数据随文件数增长 | 审阅快照也要计入总预算 |
| 比较来源标签 | 工作树↔索引、父提交↔当前、快照↔当前；接受 ≠ Git 暂存 | 低至中 | 不能为标签重新生成 diff |
| 忽略空白开关 | 仅影响阅读；写操作仍用未过滤补丁并重验内容 | 中；重算可能临时两份结果 | 不引入任意正则过滤或语义 Diff |

优先级：折叠 → 来源标签／跨文件队列 → 忽略空白。只借鉴交互，在现有 GPUI 实现；许可证未核验前不复制第三方实现。外部页面本次全部访问失败，VS Code 预期 MIT、Zed project_diff 与 GitButler 许可均待核验，Meld 预期 GPL 系。

## annotated tag 正文（2026-10-22 设计，现已实现）

语义（本机 `git` 2.54.0 手册，文档日期 2026-04-19）：annotated tag 是独立对象，有 tagger、日期、消息和可选签名；`%(contents:subject)` / `%(contents:body)` / `%(contents:signature)` 读的是 tag 对象，带 `*` 的字段才读剥离后的目标。`GIT_NO_LAZY_FETCH=1` 禁止按需拉对象，`GIT_NO_REPLACE_OBJECTS=1` 禁止 replace refs。

实现要点：完整 ref 名校验 → `for-each-ref --count=1` 取 OID／类型／大小 → 只有类型为 `tag` 且不超过 256 KiB 才读正文；不请求 textconv、filters 或签名验证；轻量标签明确说明没有独立说明；签名只标「含签名，未验证」；正文按不可信纯文本显示，非 UTF-8 标注 `lossy`。

实现与设计的差异：代码使用 `check-ref-format` + `for-each-ref` 一次读取，而不是 `cat-file -t/-s` 两步；预算与只读边界一致。现状入口：Git 图里标签菜单「查看标签详情」，提交详情不替代标签消息。

来源：<https://git-scm.com/docs/git-for-each-ref>、<https://git-scm.com/docs/git-cat-file>。
