# 开发记录：P0 / P1 首批实现

记录日期：2026 年 9 月 30 日，Asia/Shanghai。需求来源为项目根目录的「轻量代码编辑器开发说明.md」。本批按 P0 → P1 开发入口执行，GUI 路线仍是待 G1 验证的候选。

## 范围梳理与决定

1. 首版围绕多工作区、多工作树与真实文本编辑；Agent、LSP、终端、网络 Git 操作等不纳入本批。
2. 先验证真实编辑组件、窗口生命周期与资源，再接入可靠保存和产品级功能。原型输入缓冲区明确标为临时测试，不写真实文件；关闭 dirty 测试窗口需要确认。
3. 采用 `app`、`core`、`git_service` 三个 crate，复用 Kit 的 Editor 与 Markdown 组件。没有建立未来 Agent 接口或额外 GUI 抽象。
4. 已核对 v0.7.0 官方依赖配置：GPUI 使用 exact snapshot `=0.3.7`。`Cargo.lock` 固定实际依赖，未跟踪 GUI 主分支。
5. 用户允许在 `~/work` 的四个目录测试。目录清单实际包含五个非隐藏目录，本批取 `5g`、`code`、`prod`、`waibu`，不计 `data`。修订后的画像仅读取 Git index 路径、未跟踪路径和文件元数据，不执行 status 或 diff。最初画像使用过 status，Git 可能在内部读取源文件或运行 clean filter；未保留、输出或上传源码。审查后已移除该调用并重新生成画像，不能对首次运行宣称 Git 完全未读取源文件。
6. 本批关闭后台查询的 fsmonitor，避免隐式常驻 Git 进程。P2 接入事件监听时再评估既有 fsmonitor 配置与资源归属。

## 同日追加：VSCode 式工作台

用户要求左侧提供目录栏、源代码管理和搜索，右侧用于文件查看与编辑。本轮据此调整 P1 原型布局，提前少量验证 R05 / R06；不将文件打开原型视为 P2 或 P4 完成，也不改变 G1 待验证的结论。

左侧为活动栏与可调整宽度的面板。资源管理器按目录层级后台枚举，文件名搜索按需遍历路径，不建内容索引；源代码管理复用已有按仓库分组的 Git 快照。右侧包含文件标签、相对路径提示和真实 Editor。文件编辑仅在内存中，关闭 dirty 标签或窗口需要确认，`⌘S` 会显示未支持保存的提示。

文件按设备 / inode 和规范路径定位；原子替换后重复打开不会增加第二个编辑标签。跨窗口通过轻量所有者记录定位原窗口，不共享 Kit 文本 Entity。文件读取逐级锚定目录描述符，并用实际文件描述符的 metadata 判断身份、类型和大小。工作区外链接、二进制、非 UTF-8、超过 8 MiB 或单行超过 256 KiB 的文件拒绝打开，多硬链接只读。每窗口最多 20 个文件及 20 MiB 读入原文；输入增长、撤销和恢复预算仍需后续验证。

追加验证：

- `cargo test --workspace --release --locked --offline`：4 个单元测试及 1 个真实 Git 集成测试通过。最终文件读取与定位修复后，app 测试再次通过；未改动的核心 / Git 检查沿用本轮已执行结果。
- 文件检查覆盖目录链接、工作区外目标、FIFO 非阻塞拒绝、UTF-8 BOM / CRLF、硬链接、二进制、其他编码、大小和长行限制，确认读取未修改文件。
- 原生界面实测：目录打开、搜索结果定位、标签切换后的撤销与重做、dirty 标记、关闭后继续编辑、`⌘S` 提示、已暂存 / 未暂存两个不同 Diff、侧栏宽度拖动均已验证。
- 修复后的最终构建再次验证了搜索打开折叠目录里的文件，返回资源管理器后祖先已展开、当前文件已高亮；临时夹具中的同一路径经原子替换、inode 改变后，重复打开仍只有原标签，原未保存文本保留。
- GUI 编辑与 `⌘S` 后，临时夹具文件与先前内容逐项相同。随后为去重验证主动替换了夹具文件，属于单独的外部修改测试；未对真实仓库执行这些操作。

两阶段审查与 5 项问题修复见 `review.md`。跨窗口激活与异步选择失效已完成源码复查；本轮未进行跨窗口文件激活、滚动到超出视口文件、中文 IME 或新布局资源门禁的实机专项验收。

## 同日追加：原生资源选择入口

用户指出缺少主动选择目录和文件的入口。本轮在顶部增加「打开文件夹」和「打开文件」，分别绑定 `⌘⇧O` 与 `⌘O`；复用 GPUI 的 macOS 原生 NSOpenPanel，没有新增依赖。空白窗口选择文件夹后加载目录与 Git 状态；已有工作区时新开窗口，保留原窗口标签与 dirty 内容，继续限制最多五个窗口。

单独选文件不要求先打开工作区，也可选择工作区外的路径。显式选择的文件以解析目标的父目录为读取边界；文件树和搜索仍以工作区为边界，不能借此读取工作区外链接。两种入口复用已有受限读取、设备 / inode 和路径去重、跨窗口所有权及编辑标签。取消面板不会修改标签或缓冲区。

本轮验证：

- `cargo test -p workspace-editor --release --locked --offline`、app 全目标 Clippy（`-D warnings`）、fmt 与 ARM64 Release 本地打包通过。核心与 Git 服务未改动，沿用前轮验证。
- 文件检查追加显式工作区外文件及其链接目标、原入口拒绝越界、显式选择仍拒绝二进制与 FIFO；原文件内容保持一致。
- 原生界面实测按钮与两个快捷键、取消文件选择、无工作区时单独打开中文文件名的 UTF-8 文件、随后选择工作区并保留未保存标签、已有工作区时新开第二窗口，均通过。
- 第二窗口重复选择同一文件会激活原窗口，并保留原来的 dirty 标签和文本；本轮补充了上一批未执行的跨窗口文件激活验证。所有 GUI 文件操作使用临时夹具，完成后逐项核对原文件字节未变。

两阶段审查均未发现可执行问题，见 `review.md`。五窗口限制完成源码审查，本轮未重复实机窗口压力测试。G1 仍待验证；文件保存与异常恢复仍未实现。
