- 外部修改：每个文档记录设备、inode、大小、mtime 和内容哈希。只有 mtime 变了而内容没变时只更新记录。保存时磁盘已变，询问覆盖 / 重新加载（丢弃我的修改）/ 比较 / 取消；「比较」用 Diff 标签显示磁盘版本 ↔ 缓冲区。没有未保存修改的文件静默跟随磁盘（只替换变化的部分，保留光标）；有未保存修改的显示横幅「磁盘上的文件已更改」（重新加载 / 比较 / 保留我的）。磁盘内容恰好等于缓冲区时直接变为已保存。文件被删除时保留缓冲区，标签划线并标「已删除」；没改过的文件又出现时（切分支）静默重新加载。检查由文件监听事件和窗口激活触发，不轮询。
- 自动保存：关闭（默认）/ 编辑后 1 秒（防抖）/ 失去焦点时（切换标签、窗口失去焦点），存在设置文件的 `auto_save` 里。Untitled 不自动保存。
- 联动：侧栏替换遇到有未保存修改的文件时在缓冲区里替换（仍为未保存，不写盘），其余文件照旧原子写入；自己写的文件状态在写入时记录，监听事件回来时不会当成外部修改；保存后刷新所在仓库的 Git 状态，新文件所在目录重新列出；资源管理器重命名 / 移动时标签跟随，删除时未修改的标签关闭、有修改的标为「已删除」。
- 给 Agent 层：`documents::buffer_text(path, cx)` 返回任一窗口里未保存的缓冲区文本，`documents::on_buffer_saved(cx, hook)` 在每次写盘后回调。

测试（都在临时目录里）：原子写入与权限、CRLF / BOM、符号链接与硬链接、只读、外部修改的几种情况（相同 / 只动 mtime / 内容变 / 删除 / 冲突）、Untitled 另存为与重建目录、自动保存防抖、退出询问状态机、比较补丁的行对齐。

## 同日追加：缩进识别、软换行开关

- 打开文件时按 `.editorconfig` > 按内容猜测 > 语言默认确定缩进（`indent.rs`），三者逐项补齐：比如 `.editorconfig` 只写了 `indent_style = tab`，宽度就取猜测或语言默认。以前所有文件都是 Kit 默认的 2 空格，Go 文件按 Tab 也插空格。
- 猜测参照 VS Code 的 `guessIndentation`：只看前 1 万行，跳过空行；以制表符开头的行多就是制表符，否则是空格；宽度取相邻非空行前导空格差值里出现最多的（2 / 4 / 6 / 8 / 3 / 5 / 7，4 与 2 都常见时取 2）。缩进行少于 2 行不猜。制表符的宽度猜不出来，取 `.editorconfig` 或语言默认。
- `.editorconfig` 从文件所在目录向上找，到工作区文件夹或遇到 `root = true` 为止（没有工作区时找到 `/`），近的覆盖远的。支持 `*`、`**`、`?`、`{a,b}` 的节和 `indent_style`、`indent_size`、`tab_width`（含 `tab` / `unset`）；`[...]`、`{1..3}` 这类节直接跳过。和读文件在同一个后台任务里完成。
- 语言默认：Go、Makefile 用制表符（宽 4），Python、Rust、Java、C、C++ 4 空格，其余 2 空格。
- 状态栏在“行 X，列 Y”后显示“空格: 4”或“制表符长度: 4”（VS Code 中文版的写法），点击弹出菜单：使用空格缩进、使用制表符缩进、宽度 2 / 4 / 8。只改当前文档的 Tab 键行为，不改文件内容，不记住。Untitled 另存为后按新语言重设默认值。
- Kit 限制：`TabSize.tab_size` 只影响 Tab、⇧Tab 和回车自动缩进插入或去掉多少空格；GPUI 和 Kit 都没有单独排版制表符字符，它画多宽由系统排版（CoreText）决定，不随这里的宽度变化（没有在真机上量过实际宽度）。
- 软换行：代码文件默认不换行，Markdown 和纯文本（`languages.rs` 里没有语法的文件）默认换行。⌥Z（或“查看 → 自动换行”）切换当前文档，VS Code 的“查看: 切换自动换行”；只影响这个文档，不记住（Untitled 另存为后按新语言重设）。用的是 Kit 的 `EditorState::soft_wrap` / `set_soft_wrap`。Markdown 预览里点块编辑用的 `TextareaState` 是单独的状态，不受影响；预览模式下按 ⌥Z 改的是源码视图。

没有新依赖。测试：`indent.rs` 的单元测试覆盖制表符、2 / 4 空格、混合、样本不足、语言默认、节匹配、就近覆盖和 `root = true`；`indent_ui_tests.rs` 在无头窗口里打开临时文件夹里的 `.go`（制表符）、`.py`（语言默认）、`.ts`（`.editorconfig` 指定制表符），检查状态栏文字，用菜单切到空格、宽度 8 后文本不变、Tab 插入 8 个空格。`soft_wrap_ui_tests.rs` 打开 `.rs`、`.txt`、`.md` 检查默认值，在 Rust 编辑器里按 ⌥Z 两次，只有它翻转，且没有输入字符。

## 同日追加：行编辑命令

- ⌘/ 切换行注释（`editing.rs::toggle_comment`），按 VS Code 的规则：所选非空行全部已注释就取消，否则全部加上；注释符插在这些行的最小缩进处（按列算，制表符按文档的缩进宽度对齐到下一个制表位），后面跟一个空格；空行跳过（全是空行时也加）；取消时去掉注释符和其后一个空格。选区结束在某行行首时不含那一行。光标跟着文字移动，非空选区在行首插入时把注释符包进来。
- 注释符在 `languages.rs::comment_for`：Rust / JS / TS / TSX / Go / C / C++ / Java / JSON 用 `//`，Python / Shell / YAML / TOML / Makefile 用 `#`，SQL 用 `--`；没有行注释的 HTML、Markdown（`<!-- -->`）和 CSS（`/* */`）照 VS Code 退回块注释：从首行缩进处到末行行尾包成一段，首尾已是注释就去掉；纯文本和 Diff 不做事。
- 快捷键绑在 `DocumentEditor > Input`：编辑区给文档编辑器外面包了一层 `DocumentEditor` 键上下文，这些键只在文档编辑器里生效（查找框、快速打开不受影响），并且与 Kit 的 `Input` 绑定同一深度、注册在后，同键时优先于 Kit 默认（`prototype/edit_commands.rs::key_bindings`，main.rs 在 `gpui_kit::init` 之后注册）。
- 一次替换整行范围（`replace_text_in_range`，非空范围记为 Atomic），一次 ⌘Z 撤销，撤销后选区回到原处。Kit 只公开主选区（`selected_range` / `set_selected_range`），多光标时只处理主光标所在行，其余光标被收掉。
- ⌥↑ / ⌥↓ 移动行（`editing.rs::move_lines`）：所选整行块和上一行 / 下一行交换，首行上移、末行下移不动；末尾换行之后的空行也算一行（VS Code 同样）。换行符留在原位置，所以 CRLF 不变，最后一行没有换行符时换上去的行也没有，原来的行补上那个位置的换行符。选区跟着行走。
- ⇧⌥↑ / ⇧⌥↓ 复制行（`editing.rs::copy_lines`）：所选行块复制到上方或下方，选区落在新副本上（向上复制时是上面那份）；最后一行没有换行符时两份之间补一个文档的换行符（`replace::eol_of`）。
- 快捷键：Kit 在 macOS 上没有绑 ⌥↑↓ / ⇧⌥↑↓，⌥⌘↑↓ 是添加光标，保留不动；在 Linux 上 Kit 把 ⇧⌥↑↓ 绑成添加光标，这里的 `DocumentEditor > Input` 与它同深度、后注册，所以复制行优先，不需要 `NoAction` 解绑。移动和复制都是一次替换，一次 ⌘Z 撤销。
- ⌘D（`editing.rs::word_at` / `next_occurrence`）：没有选区时选中光标处的词（字母、数字、下划线，含中文）；有选区时找它后面下一个相同文本，区分大小写，到末尾回绕；选区是 ⌘D 从光标处的词得来的，就只匹配整词（VS Code 同样），手动选的按子串找。⌘D 和 ⇧⌘L 原来都没有绑定（main.rs 和 Kit 默认都没有）。
- Kit 的多选区：`InputBaseState` 内部有多个选区（`selections: Selections`，⌥⌘↑↓ 添加光标、⌥ 点击、列选都会用到），但字段和 `add_cursor_at` / `build_columnar_selection` 都是 `pub(super)`；公开的只有 `selected_range`（主选区）和 `set_selected_range`（设置主选区并去掉其他光标），读不到也加不了额外选区。在 Kit 之外只能靠合成 ⌥ 点击之类的鼠标事件，只能加空光标、依赖可见位置，不可靠；registry 源码不能改，为此 vendor gpui-base 又太大。所以 ⌘D 退化为移动这一个选区（相当于 VS Code 的 ⌘K ⌘D），⇧⌘L（选中全部）没有实现、也没有绑定。等 Kit 公开设置多选区的接口后再补。

没有新依赖。测试：`editing.rs` 的单元测试覆盖加 / 去注释、混合、空行、缩进不一致（含制表符）、CRLF 和块注释，移动的首末行边界、多行块、末行无换行和 CRLF，以及向上 / 向下复制；`edit_commands_ui_tests.rs` 在临时 `.rs` 文件里选中两行按 ⌘/ 检查文本和选区，再按一次复原，⌘Z 一步撤销；按 ⌥↓ 移动一行（到末行后不再动、两次 ⌘Z 复原）、⇧⌥↓ 复制一行并检查光标落在副本上；按 ⌘D 选中光标处的 `id`，再按跳过 `idx` 到下一个整词 `id`，最后回绕。单元测试还覆盖取词（词首、词尾、下划线、中文、空白处）和查找（回绕、大小写、整词与子串、只有一处、跨行选区）。

## 同日追加：运行中内存现场分析

用户报告 Vorssaint 在 09:15 显示 ZJ 占用 1.39 GB。09:32–09:41 对运行中的原进程采样；没有重启 ZJ、停止 Agent 或改变用户窗口。该进程从前一日 20:34 启动，现场会话仍在运行。本轮修改后的二进制尚未载入原进程。

所有下表数值以十进制 MB 计。`footprint` 与 `proc_pid_rusage` 用于读取物理占用，`vmmap` 和 `heap` 用于分类；不同时间的快照不直接相加。

| --- | ---: | --- |
| ZJ 主进程（PID 86446） | 单次 508.7 MB；首段采样平均 505.8 MB | 单次记录峰值 578.5 MB |
| Codex 本体（PID 16140） | 单次 125.9 MB；首段采样平均 123.1 MB | 不包含它启动的工具、MCP 和辅助进程 |

主进程的首份分类中，IOSurface 153.0 MB、图形 owned-unmapped 128.4 MB、IOAccelerator 48.0 MB，合计约 329 MB，约占主进程的 65%。Malloc Small 115.7 MB，Malloc Large 9.5 MB。后续 `vmmap -v` 看到 4 块 3456 × 2168 的 Display Drawable，每块 29.2 MiB（约 30.6 MB）；表面数量不等同窗口数量。`heap` 看到约 103.7 MB 的分配，其中 93.3 MB 无对象类型信息；未启用分配栈，不能据此把它全部归因于会话文本或内存泄漏。

结论：Codex 运行确实增加进程树内存，但 Codex 本体不能独自解释 1.39 GB；现场有多个 Node、MCP、工具及辅助 Codex 进程。ZJ 主进程自己的图形占用也偏高。尚未核实 Vorssaint 的计算口径，也未复现截图时刻的 1.39 GB 峰值，因此不能把截图值直接当作 ZJ 主进程的物理占用。

源码解释了一项运行与空闲的差别：Agent 的运行指示器每 125 ms 更新前台工作台；GPU 备用 drawable 的回收要求连续 3 秒没有新帧。运行时的动画和输出会阻止这项空闲回收。现有会话上限是每线程 400 条、工具正文每条 16 KiB、高亮缓存 256 块；条数限制不是总字节限制，长回复和渲染缓存仍需单独评估。当前证据未证明持续泄漏。

后续验证应在相同窗口和文件数量下对比任务运行、结束后空闲、隐藏窗口三个状态，分别记录主进程和子进程，优先检查 GPU 资源回收与会话总字节预算。此次仅分析，没有据此修改渲染器或 Agent 缓存策略。原始采样保存在 `/private/tmp/zj-live-memory.csv`、`/private/tmp/zj-live-memory-build.csv`；分类保存在 `/private/tmp/zj-live-vmmap-summary.txt`、`/private/tmp/zj-live-vmmap-regions.txt` 和 `/private/tmp/zj-live-heap.txt`。
