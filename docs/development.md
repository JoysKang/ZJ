1. 首版围绕多工作区、多工作树与真实文本编辑；Agent、LSP、终端、网络 Git 操作等不纳入本批。

## 同日追加：VSCode 式工作台

用户要求左侧提供目录栏、源代码管理和搜索，右侧用于文件查看与编辑。本轮据此调整 P1 原型布局，提前少量验证 R05 / R06；不将文件打开原型视为 P2 或 P4 完成，也不改变 G1 待验证的结论。

左侧为活动栏与可调整宽度的面板。资源管理器按目录层级后台枚举，文件名搜索按需遍历路径，不建内容索引；源代码管理复用已有按仓库分组的 Git 快照。右侧包含文件标签、相对路径提示和真实 Editor。文件编辑仅在内存中，关闭 dirty 标签或窗口需要确认，`⌘S` 会显示未支持保存的提示。

文件按设备 / inode 和规范路径定位；原子替换后重复打开不会增加第二个编辑标签。跨窗口通过轻量所有者记录定位原窗口，不共享 Kit 文本 Entity。文件读取逐级锚定目录描述符，并用实际文件描述符的 metadata 判断身份、类型和大小。工作区外链接、二进制、非 UTF-8、超过 8 MiB 或单行超过 256 KiB 的文件拒绝打开，多硬链接只读。每窗口最多 20 个文件及 20 MiB 读入原文；输入增长、撤销和恢复预算仍需后续验证。

## 2026 年 10 月 1 日追加：工作区自动刷新

本轮先核对用户两版修改后的代码与 `CLAUDE.md`。基准为 `e2f0613fa5c95d48c0ee71152cb03620f036d777`，开始时工作区干净；保留用户的主题、图标、模糊路径搜索及工作台模块结构。本批推进 T12 / P2 的文件与 Git 事件刷新，涉及 A09 的外部修改收敛验证；不将 T12、P2 或 G1 标为完成。

实现使用一份应用级原生监听器和按窗口订阅。先监听工作区，再建立初始快照；仓库发现后，在首次 status 前接入工作区外的 Git common/private 目录。共享路径按引用回收；关闭最后一个订阅后停止监听。窗口信号容量为 1，合并事件与错误，空闲时没有磁盘轮询。事件按 200 ms 合并，连续变化最多合并 1 秒；在途扫描结束后补查，并继续用 generation 拒绝旧结果。恢复焦点和事件溢出也触发补查。

- 正则分组 `$1`、`${name}`；
- `\u` `\U` 等大小写转义；
- 保留大小写；
- CRLF；
- 多字节文本；
- 匹配不跨行。

侧栏搜索加入替换：

- 结果行内预览删除线和替换文字；
- 悬停一行出现替换 / 忽略，悬停一个文件出现全部替换 / 忽略；
- 点击结果打开替换前后的 Diff；
- 全部替换前确认数量。

写文件时用临时文件加 rename 原子替换。搜索后被改过的文件（设备、inode、大小、修改时间，或匹配已不在原处）会跳过；符号链接、多硬链接文件，以及在任一窗口有未保存编辑的文件也会跳过。打开着且没改过的缓冲区只替换变化的部分，并保留光标。最后一次替换可以撤销。

Xvfb 上验证（release 构建）：

- 查找：“Agent”6 项。替换一项后 5 项；全部替换后无结果，状态栏显示“已替换 5 处”；⌘Z 一次恢复 6 项。
- 侧栏替换：替换后文件里不再有“Agent”；撤销后 `git status` 干净，文件逐字节恢复。打开着、未修改的文件随之更新，不标记为已修改，视图不跳动。
- 跳过：有未保存编辑的文件跳过且未写入；搜索后在外部追加了一行的文件跳过并提示“文件在搜索后已修改”。

Linux 上 X11 把 ⇧1 报成“!”，所以“替换”另外绑定了 `secondary-!`；macOS 上的 ⌘⇧1 需要实机确认。

1 个窗口时 67 MB 的 Malloc Small：在 Linux 上用 heaptrack 看同类工作区，应用侧常驻堆只有约 8 MB，其余是软件渲染。因此判断 Mac 上的大头在系统框架里，ADR 0005 写了在 Mac 上定位的办法。

## 2026 年 10 月 2 日追加：第 8 批 a（保存）

文件可以保存了，行为按 VS Code，只做轻量的部分。纯逻辑在 `save.rs`，工作台一侧在 `prototype/documents.rs`。

- 键位和菜单：`⌘S` 保存，`⇧⌘S` 另存为（系统保存面板），`⌥⌘S` 全部保存，`⌘N` 新建 Untitled-N（第一次保存时另存为），`⌘Q` / 「退出 ZJ」。「文件」菜单里有对应项目和「自动保存」子菜单。

- 写入：同目录临时文件 `.名字.zj-save-PID`，fsync 后 rename，再 fsync 目录；保留权限位。换行符在打开时识别，CRLF 文档里编辑器输入的 `\n` 写成 `\r\n`；保留 UTF-8 BOM；文件末尾换行保持原样。符号链接写到目标（链接本身不变）；多硬链接文件截断后原地写，保持同一个 inode；没有写权限时提示并提供「另存为」。已删除的文件（连同目录）保存时重新创建。
- 外部修改：每个文档记录设备、inode、大小、mtime 和内容哈希。只有 mtime 变了而内容没变时只更新记录。保存时磁盘已变，询问覆盖 / 重新加载（丢弃我的修改）/ 比较 / 取消；「比较」用 Diff 标签显示磁盘版本 ↔ 缓冲区。没有未保存修改的文件静默跟随磁盘（只替换变化的部分，保留光标）；有未保存修改的显示横幅「磁盘上的文件已更改」（重新加载 / 比较 / 保留我的）。磁盘内容恰好等于缓冲区时直接变为已保存。文件被删除时保留缓冲区，标签划线并标「已删除」；没改过的文件又出现时（切分支）静默重新加载。检查由文件监听事件和窗口激活触发，不轮询。
- 自动保存：关闭（默认）/ 编辑后 1 秒（防抖）/ 失去焦点时（切换标签、窗口失去焦点），存在设置文件的 `auto_save` 里。Untitled 不自动保存。
- 联动：侧栏替换遇到有未保存修改的文件时在缓冲区里替换（仍为未保存，不写盘），其余文件照旧原子写入；自己写的文件状态在写入时记录，监听事件回来时不会当成外部修改；保存后刷新所在仓库的 Git 状态，新文件所在目录重新列出；资源管理器重命名 / 移动时标签跟随，删除时未修改的标签关闭、有修改的标为「已删除」。
- 给 Agent 层：`documents::buffer_text(path, cx)` 返回任一窗口里未保存的缓冲区文本，`documents::on_buffer_saved(cx, hook)` 在每次写盘后回调。

测试（都在临时目录里）：原子写入与权限、CRLF / BOM、符号链接与硬链接、只读、外部修改的几种情况（相同 / 只动 mtime / 内容变 / 删除 / 冲突）、Untitled 另存为与重建目录、自动保存防抖、退出询问状态机、比较补丁的行对齐。

已知限制：

## 同日追加：缩进识别、软换行开关

- 打开文件时按 `.editorconfig` > 按内容猜测 > 语言默认确定缩进（`indent.rs`），三者逐项补齐：比如 `.editorconfig` 只写了 `indent_style = tab`，宽度就取猜测或语言默认。以前所有文件都是 Kit 默认的 2 空格，Go 文件按 Tab 也插空格。

## 同日追加：行编辑命令

- ⌘/ 切换行注释（`editing.rs::toggle_comment`），按 VS Code 的规则：所选非空行全部已注释就取消，否则全部加上；注释符插在这些行的最小缩进处（按列算，制表符按文档的缩进宽度对齐到下一个制表位），后面跟一个空格；空行跳过（全是空行时也加）；取消时去掉注释符和其后一个空格。选区结束在某行行首时不含那一行。光标跟着文字移动，非空选区在行首插入时把注释符包进来。

- ⌥↑ / ⌥↓ 移动行（`editing.rs::move_lines`）：所选整行块和上一行 / 下一行交换，首行上移、末行下移不动；末尾换行之后的空行也算一行（VS Code 同样）。换行符留在原位置，所以 CRLF 不变，最后一行没有换行符时换上去的行也没有，原来的行补上那个位置的换行符。选区跟着行走。
- ⇧⌥↑ / ⇧⌥↓ 复制行（`editing.rs::copy_lines`）：所选行块复制到上方或下方，选区落在新副本上（向上复制时是上面那份）；最后一行没有换行符时两份之间补一个文档的换行符（`replace::eol_of`）。
- 快捷键：Kit 在 macOS 上没有绑 ⌥↑↓ / ⇧⌥↑↓，⌥⌘↑↓ 是添加光标，保留不动；在 Linux 上 Kit 把 ⇧⌥↑↓ 绑成添加光标，这里的 `DocumentEditor > Input` 与它同深度、后注册，所以复制行优先，不需要 `NoAction` 解绑。移动和复制都是一次替换，一次 ⌘Z 撤销。
- ⌘D（`editing.rs::word_at` / `next_occurrence`）：没有选区时选中光标处的词（字母、数字、下划线，含中文）；有选区时找它后面下一个相同文本，区分大小写，到末尾回绕；选区是 ⌘D 从光标处的词得来的，就只匹配整词（VS Code 同样），手动选的按子串找。⌘D 和 ⇧⌘L 原来都没有绑定（main.rs 和 Kit 默认都没有）。
- Kit 的多选区：`InputBaseState` 内部有多个选区（`selections: Selections`，⌥⌘↑↓ 添加光标、⌥ 点击、列选都会用到），但字段和 `add_cursor_at` / `build_columnar_selection` 都是 `pub(super)`；公开的只有 `selected_range`（主选区）和 `set_selected_range`（设置主选区并去掉其他光标），读不到也加不了额外选区。在 Kit 之外只能靠合成 ⌥ 点击之类的鼠标事件，只能加空光标、依赖可见位置，不可靠；registry 源码不能改，为此 vendor gpui-base 又太大。所以 ⌘D 退化为移动这一个选区（相当于 VS Code 的 ⌘K ⌘D），⇧⌘L（选中全部）没有实现、也没有绑定。等 Kit 公开设置多选区的接口后再补。

没有新依赖。测试：`editing.rs` 的单元测试覆盖加 / 去注释、混合、空行、缩进不一致（含制表符）、CRLF 和块注释，移动的首末行边界、多行块、末行无换行和 CRLF，以及向上 / 向下复制；`edit_commands_ui_tests.rs` 在临时 `.rs` 文件里选中两行按 ⌘/ 检查文本和选区，再按一次复原，⌘Z 一步撤销；按 ⌥↓ 移动一行（到末行后不再动、两次 ⌘Z 复原）、⇧⌥↓ 复制一行并检查光标落在副本上；按 ⌘D 选中光标处的 `id`，再按跳过 `idx` 到下一个整词 `id`，最后回绕。单元测试还覆盖取词（词首、词尾、下划线、中文、空白处）和查找（回绕、大小写、整词与子串、只有一处、跨行选区）。

按用户的决定实现：进入终端总是切到英文输入法，要用别的在终端里自己切；点 Agent 输入框时切回上次在那里用的输入法，第一次用之前见过的非英文输入法，都没见过就用系统里第一个启用的输入法；编辑器不管；所有终端共用同一规则；设置 `auto_input_source` 默认开启。

- 实现：`platform.rs` 用 Carbon 的 Text Input Sources（`TISCopyCurrentKeyboardInputSource`、`TISCopyCurrentASCIICapableKeyboardInputSource`、`TISSelectInputSource`、`TISCreateInputSourceList`）读取和切换，切换后让当前文本输入上下文重新激活一次，防止部分第三方输入法只改了菜单栏、实际没有生效；`input_switch.rs` 是纯逻辑；`workbench/input_area.rs` 接在终端和输入框的 focus-in、输入框的 focus-out 和窗口激活上。只在窗口在前台时切换，没有定时器。没有新增依赖。
- 原型：在用户机器上（ABC + 微信输入法拼音）切到 ABC 和切回微信输入法各约 10 ms，系统报告的当前输入源随之改变。是否能立刻打出中文，需要用户实际打字确认（这里不能向窗口发送按键）。
- 测试：新增纯逻辑单元测试 3 项；测试构建里输入源接口是空实现，跑完全部测试后用户的输入法保持不变。全工作区测试和 Clippy 通过。dist 二进制 29,711,616 字节，低于 30 MB 目标。本地 `target/ZJ.app` 已更新，重启后生效。
