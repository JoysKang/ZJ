# 开发记录：P0 / P1 首批实现

记录日期：2026 年 9 月 30 日，Asia/Shanghai。需求来源为项目根目录的「轻量代码编辑器开发说明.md」。本批按 P0 → P1 开发入口执行，GUI 路线仍是待 G1 验证的候选。

## 范围梳理与决定

1. 首版围绕多工作区、多工作树与真实文本编辑；Agent、LSP、终端、网络 Git 操作等不纳入本批。
2. 先验证真实编辑组件、窗口生命周期与资源，再接入可靠保存和产品级功能。原型输入缓冲区明确标为临时测试，不写真实文件；关闭 dirty 测试窗口需要确认。
3. 采用 `app`、`core`、`git_service` 三个 crate，复用 Kit 的 Editor 与 Markdown 组件。没有建立未来 Agent 接口或额外 GUI 抽象。
4. 已核对 v0.7.0 官方依赖配置：GPUI 使用 exact snapshot `=0.3.7`。`Cargo.lock` 固定实际依赖，未跟踪 GUI 主分支。
5. 用户允许在 `~/work` 的四个目录测试。目录清单实际包含五个非隐藏目录，本批取 `5g`、`code`、`prod`、`waibu`，不计 `data`。修订后的画像仅读取 Git index 路径、未跟踪路径和文件元数据，不执行 status 或 diff。最初画像使用过 status，Git 可能在内部读取源文件或运行 clean filter；未保留、输出或上传源码。审查后已移除该调用并重新生成画像，不能对首次运行宣称 Git 完全未读取源文件。
6. 本批关闭后台查询的 fsmonitor，避免隐式常驻 Git 进程。P2 接入事件监听时再评估既有 fsmonitor 配置与资源归属。

## 同日追加：VSCode 式工作台

用户要求左侧提供目录栏、源代码管理和搜索，右侧用于文件查看与编辑。本轮据此调整 P1 原型布局，提前少量验证 R05 / R06；不将文件打开原型视为 P2 或 P4 完成，也不改变 G1 待验证的结论。

左侧为活动栏与可调整宽度的面板。资源管理器按目录层级后台枚举，文件名搜索按需遍历路径，不建内容索引；源代码管理复用已有按仓库分组的 Git 快照。右侧包含文件标签、相对路径提示和真实 Editor。文件编辑仅在内存中，关闭 dirty 标签或窗口需要确认，`⌘S` 会显示未支持保存的提示。

文件按设备 / inode 和规范路径定位；原子替换后重复打开不会增加第二个编辑标签。跨窗口通过轻量所有者记录定位原窗口，不共享 Kit 文本 Entity。文件读取逐级锚定目录描述符，并用实际文件描述符的 metadata 判断身份、类型和大小。工作区外链接、二进制、非 UTF-8、超过 8 MiB 或单行超过 256 KiB 的文件拒绝打开，多硬链接只读。每窗口最多 20 个文件及 20 MiB 读入原文；输入增长、撤销和恢复预算仍需后续验证。

## 2026 年 10 月 1 日追加：工作区自动刷新

本轮先核对用户两版修改后的代码与 `CLAUDE.md`。基准为 `e2f0613fa5c95d48c0ee71152cb03620f036d777`，开始时工作区干净；保留用户的主题、图标、模糊路径搜索及工作台模块结构。本批推进 T12 / P2 的文件与 Git 事件刷新，涉及 A09 的外部修改收敛验证；不将 T12、P2 或 G1 标为完成。

实现使用一份应用级原生监听器和按窗口订阅。先监听工作区，再建立初始快照；仓库发现后，在首次 status 前接入工作区外的 Git common/private 目录。共享路径按引用回收；关闭最后一个订阅后停止监听。窗口信号容量为 1，合并事件与错误，空闲时没有磁盘轮询。事件按 200 ms 合并，连续变化最多合并 1 秒；在途扫描结束后补查，并继续用 generation 拒绝旧结果。恢复焦点和事件溢出也触发补查。

自动刷新同时更新目录、路径索引和 Changes，保留目录展开意图。手动折叠优先；已知工作树内的事件不按 `target` 等目录名过滤，Git 决定实际变更。文件标签、dirty 内容和撤销历史不重载；已打开 Diff 保留快照并显示过期提示。监听失败在状态栏显示异常，用户仍可手动刷新。新增 `watch.rs` 负责原生监听与引用，`prototype/workspace_refresh.rs` 负责界面刷新编排；未增加 GUI 抽象或升级 GUI 依赖。

- 外部修改：每个文档记录设备、inode、大小、mtime 和内容哈希。只有 mtime 变了而内容没变时只更新记录。保存时磁盘已变，询问覆盖 / 重新加载（丢弃我的修改）/ 比较 / 取消；「比较」用 Diff 标签显示磁盘版本 ↔ 缓冲区。没有未保存修改的文件静默跟随磁盘（只替换变化的部分，保留光标）；有未保存修改的显示横幅「磁盘上的文件已更改」（重新加载 / 比较 / 保留我的）。磁盘内容恰好等于缓冲区时直接变为已保存。文件被删除时保留缓冲区，标签划线并标「已删除」；没改过的文件又出现时（切分支）静默重新加载。检查由文件监听事件和窗口激活触发，不轮询。
- 自动保存：关闭（默认）/ 编辑后 1 秒（防抖）/ 失去焦点时（切换标签、窗口失去焦点），存在设置文件的 `auto_save` 里。Untitled 不自动保存。
- 联动：侧栏替换遇到有未保存修改的文件时在缓冲区里替换（仍为未保存，不写盘），其余文件照旧原子写入；自己写的文件状态在写入时记录，监听事件回来时不会当成外部修改；保存后刷新所在仓库的 Git 状态，新文件所在目录重新列出；资源管理器重命名 / 移动时标签跟随，删除时未修改的标签关闭、有修改的标为「已删除」。
- 给 Agent 层：`documents::buffer_text(path, cx)` 返回任一窗口里未保存的缓冲区文本，`documents::on_buffer_saved(cx, hook)` 在每次写盘后回调。

测试（都在临时目录里）：原子写入与权限、CRLF / BOM、符号链接与硬链接、只读、外部修改的几种情况（相同 / 只动 mtime / 内容变 / 删除 / 冲突）、Untitled 另存为与重建目录、自动保存防抖、退出询问状态机、比较补丁的行对齐。

## 同日追加：Git 图按 Git Graph 扩展重做车道布局

对照 VS Code Git Graph 扩展的 README 和画图源码 `web/graph.ts` 调整：

- 车道布局（`prototype/graph_view.rs` 的 `layout`）移植自 `web/graph.ts`：沿第一父提交向下走成一条分支，每一行取第一条空闲车道，所以左边的车道空出后右边的线会斜着移过去，图不留空隙；两个兄弟提交的线各自走到共同父提交才汇合，不再在下一行就并进另一条线；合并边在目标分支的线经过的那一行接进去；分支结束后它的颜色给后面的分支复用。父提交不在已加载的页里时，线一直画到最后一行。换车道画成 Git Graph 的 S 形三次曲线（从一行的节点高度到下一行的），在行边界处拆成两半，每行只画上一行下来的下半段和本行出去的上半段，列表仍然虚拟化。
- HEAD 节点改成空心圆（描边路径，行的悬停 / 选中底色会透出来）。引用标签用所在车道的颜色描边，图标也用车道颜色，文字颜色不变。
- 右键菜单和悬停提示重叠：原来整行有悬停提示，右键菜单打开后鼠标还在这一行上，提示过一会儿又出现。现在去掉整行提示，和 Git Graph 一样只在悬停节点时提示：提交短哈希、是否包含在 HEAD 中（HEAD 所在提交已加载时）、包含该提交的分支和标签（该提交及其已加载的后代上的引用，超过 10 个只留前后各 5 个）。提示在打开时才计算，render 里不遍历历史。
- 入口：曾把仓库标题里的 Git 图按钮（和分支图标相像）移到状态栏，按用户意见已改回，仍在仓库标题和 ··· 菜单里。同步和刷新两个循环箭头保持不变。

没有做的 Git Graph 功能：顶部“未提交的更改”行、⌘ 点击比较两个提交、键盘切换详情、合并提交淡色、同名本地 / 远程分支合并成一个标签。

体积：与 `4f6ebeb` 相比，dist 二进制增加 16,528 字节（34,894,240 → 34,910,768），normal 依赖树 601 不变。

测试：`graph_view.rs` 的布局单测改为检查每行的车道和向下的线（线性、合并后两条线走到共同的父提交、兄弟提交、车道空出后左移、颜色复用、父提交未加载），新增随机历史测试（50 组、每组最多 121 个提交，检查布局能结束、每条线上下连续不悬空）和节点提示的内容测试；`graph_ui_tests.rs` 的车道形状断言随之更新。`tools/check_git_deadlines.py` 通过。界面没有在真机上截图验证，曲线和空心圆的实际效果需要打开看。
