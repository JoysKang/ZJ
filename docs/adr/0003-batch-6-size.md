# ADR 0003：资源管理器文件操作、全文搜索、设置与新图标的体积

日期：2026-10-02。状态：已采纳。

## 背景

按 `CLAUDE.md`，二进制增加超过 200 KB 要单独记录。本批（第 6 批）一次加入了用户要的几项功能：资源管理器右键菜单与文件操作、VS Code 式全文搜索、设置文件、多仓库源码管理的提交框，以及新的应用图标和欢迎页 logo。

## 决定

接受下面的增量，不为体积删减功能：

| 构建（Linux x86_64，`--profile dist`，stripped）| 字节 | 差值 |
| --- | ---: | ---: |
| 第 5 批（5108c9d）| 48,701,552 | |
| 第 6 批功能（图标前，7765163）| 49,114,096 | +412,544 |
| 加新图标（ecb088c）| 49,185,392 | +71,296 |
| 合计 | | **+483,840** |

- 依赖不变：`regex 1` 和 macOS 上的 `objc2 0.6` 本来就在依赖树里，只改成直接依赖；`Cargo.lock` 没有新增包，`cargo tree -e normal` 去重行数 582 → 582。增量全部是本项目自己的代码和资源。
- 功能部分约 400 KB：全文搜索（glob 转正则、多线程遍历、按文件分组的虚拟列表）、文件操作（新建 / 重命名 / 复制 / 移动 / 废纸篓）与行内编辑、设置读写、每个仓库的提交框和下拉菜单，以及这些处理器在 GPUI 泛型里的单态化。
- 图标部分约 70 KB：欢迎页 logo 两张 PNG 共 50.5 KB（干笔滤镜 resvg 画不平滑，改用浏览器按 3 倍预渲染），其余是光标视图和 `platform.rs`。macOS 上还多嵌一张 40 KB 的 Dock 无光标帧。

## 代价与后果

- aarch64 macOS 上的绝对值会不同，但增量量级应相近；仍远低于 52 MB 上限。
- 内存没有因此变大：4 个窗口 / 60 个仓库的 RSS 从 301.7 MB 降到 297.4 MB（快速打开索引改为紧凑存储），见 `docs/development.md`。
- 以后再加功能时，先看这一批的单态化开销：新的 GPUI 视图尽量复用已有的列表 / 菜单组件，不另写一套。
