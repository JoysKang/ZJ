# ADR 0002：不跑语言服务器的代码跳转

日期：2026-10-01。状态：已采纳。

## 背景

用户要求「代码跳转」，前提是资源消耗小、支持多语言。LSP 每种语言一个常驻进程，几百 MB 内存，和本项目「低资源」的定位冲突，`CLAUDE.md` 也把 LSP 排除在首版之外。

## 决定

只用已经编进来的 tree-sitter 语法：

- **文件内**：每种语言一份小的 `locals` 查询（作用域 + 局部绑定：参数、`let`、赋值、for 变量……），按「最内层作用域、离引用最近的定义」解析。JS / TS 用语法包自带的 `locals.scm`，其余语言是本项目写的最小版本（`crates/app/queries/*-locals.scm`）。
- **跨文件**：语法包自带的 `tags.scm`（GitHub 代码导航用的同一套定义 / 引用捕获），再补一些常量、字段、宏（`*-extra-tags.scm`）。工作区符号索引在第一次跳转时由后台线程建立（最多 4 个线程，单文件上限 1 MiB），只存「名字 → 定义位置」，用排好序的扁平数组加一份名字文本；文件监听只重解析变化的文件。
- **引用（⇧F12）不常驻**：按需扫描包含该名字的文件。
- **歧义**：同文件唯一定义直接跳；`db::connect` 这种限定名优先匹配同名模块文件；只保留同语言的候选；其余按同目录、被导入、路径接近度排序，多个时弹出列表。
- **界面**：复用 Kit 编辑器的 `DefinitionProvider`（⌘ 悬停下划线、⌘ 单击、F12）和 `show_document` 钩子；⌘⇧O、⇧F12、⌃- / ⌃⇧- 走工作台自己的列表和历史。

支持 Rust、Python、JavaScript、TypeScript、TSX、Go、C、C++、Java、Bash。

## 代价

- 依赖：直接依赖 `lsp-types =0.97.0`（Kit 编辑器本来就依赖，不新增 crate）。查询文本约 20 KB；二进制增量与 C / C++ / Java / SQL 语法一起计在 ADR 0001 的补充里。
- 建索引（Linux x86_64，release，4 线程；5,140 个源文件 / 58.7 MB / 148,064 个定义）：3.4 s；索引本身约 5.8 MB；单独测量时建完并归还空闲页后 RSS 增加约 6.5 MB。在应用里对同一目录第一次 F12：后台 3.7 s 建完，进程 RSS 增加 14.3 MB（其中包括这个目录里出现的各语言 tags 查询）。之后空闲 CPU 为 0（没有定时器，只有文件事件触发的增量更新）。
- 查询按语言、按用途懒编译：索引只编译 tags；某种语言的文件第一次跳转时才编译它的 locals。tags 查询常驻内存：C++、TypeScript 约 3.2 MB，Bash、Python、C 约 1.5–2 MB，其余不到 1.5 MB。

## 后果

- 结果是启发式的：同名函数、方法重载、宏生成的符号、动态语言里的属性访问可能给出多个候选或找不到，这时用列表让用户选。
- 以后如果要更准，可以再加按语言的 import 解析，或者把 LSP 作为可选项；本方案不妨碍这两条路。

## 2026-10-13 补充：Diff 版本内跳转

Diff 支持 ⌘单击、F12 和 ⌃G 转到行。点击用 GPUI 文本布局命中 UTF-8 字节列；原补丁只在定义请求期间后台还原，保留 Tab 与作用域，不常驻额外全文副本。同文件目标及多候选列表跳到所选 Diff 侧，删除文件也保留旧版本；跨文件目标复用当前工作区的磁盘符号索引，因此不能保证历史跨文件版本一致。补丁或请求已变化时丢弃旧结果；导航历史用弱引用识别 Diff 文档，不延长全文的存活时间。没有完整上下文或可解析源码时说明原因，不猜测定义位置。

## 2026-10-13 补充：import 参与排序、局部变量着色

跨文件候选不再只看源码里是否出现过候选文件名。`crates/app/src/imports.rs` 按语言读 import 语句（`use` / `mod` / `import` / `from` / `#include` / `source` / `require(` 等；跨行语句按行尾是开括号或逗号续行），返回其中的模块名与符号名；`symbol_index::rank` 据此排序（import 到的模块或引用本身的符号名优先于「源码里提过这个名字」），`workbench::navigation::resolve` 在既有的「限定名唯一」之外新增一条：import 的模块名唯一命中一个候选时直接决定跳转，不再弹列表。文件名到模块名的换算统一在 `symbol_index::module_name`（`mod.rs` / `index.ts` / `__init__.py` 取目录名），原有限定名规则改用它，行为不变。只影响候选排序与唯一判定，不动 tags / locals 查询，不新增依赖。

`symbols::bindings` 复用同一套 `locals` 查询与「最内层作用域、离引用最近」规则，把 `local.definition` 与其引用配对（定义自身也被 `(identifier)` 捕获为引用，跳过）。`workbench/local_vars.rs` 给每个绑定取一个主题色（`theme::Colors::bindings` 四色，取自 git 状态色，两种主题都按编辑器背景 4.5:1 校验），用 Kit 的 `TextDecorationCollection` 给定义与引用着色。只在打字停顿 250 ms 后、为当前可见文档在后台重算，切换标签时补算；上限 1 MiB 文件、512 个绑定、8192 个着色区间，超出部分留归语法色。为此给本项目自写的 7 份 locals 查询加了 `local.reference` 捕获（Rust / Python / Go / C / C++ / Java 用 `(identifier)`，Bash 用 `(variable_name)`）；JS / TS 原本就有。着色是装饰层，不改文本、选区、换行和撤销。
