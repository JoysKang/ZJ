# ADR 0008：升级 GPUI Kit 到 0.7.1

日期：2026-10-07。状态：已采纳，资源短测存在波动。

## 决定

按用户要求将 `gpui-kit` 固定为 `=0.7.1`，同步升级其组件和 GPUI 依赖。GPUI 版本从 0.3.7 升为 0.3.8，三个 vendor crate 按发布源码迁移并保留 ZJ 补丁，不增加应用自身的依赖或 feature。

保留常亮光标、行尾 blame、一次性视口定位、共享图集、双缓冲、闲置表面释放及 display link 停帧。合并时保留新上游的水平对齐和 textarea 滚动边界、帧信号来源与时间、shared-storage 策略及仅调试构建使用的截图配置。Metal 表面尺寸使用已有的类型化 API，避免恢复已移除的旧 Objective-C 接口。

## 依赖与资源

测量使用 `aarch64-apple-darwin`、dist 产物及隔离临时工作区；footprint 包含 Git 子进程。全场景每版的冷启动均为单次测量，空闲 CPU 采样 5 秒。原始数据保存在 `docs/reports/gpui-071-*.json`。

二进制增加 66,176 字节，低于 30 MB 目标。单文档 footprint 短测增加超过 5 MB，因此记录此决策；两轮仍低于 100 MB 上限，但超过 70 MB 目标。CPU 短测未满足 p95 ≤ 0.1% 的预算，不能把本次资源验收标为全部达标。

进一步用相同小文件对照两版，等到 display link 停止后采样约 16 秒：新版 footprint 为 55.40 MB、平均 CPU 0.00177%，旧版 footprint 为 55.58–68.88 MB、平均 CPU 0.449%。线程采样均停在系统等待；旧版日志也出现晚到的唤醒和出帧。独立忙循环对照 `getrusage` 确认当前工具的 Mach 时间换算正确，没有修改测量口径。这些结果未建立稳定的升级回归，也不足以确定波动来源；平均 CPU 与前表 p95 不可直接比较。

## 验证与限制

全工作区测试、fmt、Clippy、Git 子进程 deadline 检查及 dist 构建通过。输入框边界回归覆盖 300–900 px、运行与空闲状态、长 Agent / 模式 / 模型标签和额度按钮。静态复核确认 ZJ 补丁保留；实际窗口日志确认闲置 display link 会停止。

采纳升级并保留完整实测数据。后续若排查资源预算，应固定窗口前后台状态、延长采样并区分输入或系统事件触发的唤醒，不根据单次短测归因或新增常驻计时器。
